# Режимные показатели миссии, версия 1

Дата определения: 2026-09-08. Реализация: `cleanup_sim_v2/regimes.py`,
`cleanup_sim_v2/analyze_regimes.py`; снимки в `simulation.py`.
Это слой измерений для пункта 2 текущего плана, а не правило выбора победителя.
Порогов рекомендации режимов здесь нет; параметры физики и планировщиков не меняются.

## Обозначения и доступность данных

- W — полная ширина захвата, м; u — скорость сбора, м/с; Δ — период сенсоров, с.
- v — модуль заданной фоновой скорости течения + windage, м/с; D — диффузивность,
  м²/с; Tstale — срок удаления неподтвержденной свежим наблюдением цели, с.
- d — прямое расстояние от робота до назначенной точки, м.
- mi — ожидаемое число объектов в ячейке карты, N — число ячеек.
- Возраст track равен t − last_seen; координаты и σ берутся из оценки track,
  не из истинного положения частицы. σ — модельный масштаб ошибки одной координаты.

Новые поля `regime_*` записываются в `goal_started` после выбора цели и до движения.
Это **назначения участков**, включая продолжение очереди. Они не являются частотами
вызовов adaptive selector. Oracle-переуточнения `goal_updated` здесь не усредняются.
Снимок не меняет tracks/карту/очередь, не вызывает prune и не использует RNG или
истинный debris field. Реальные исходы и false/true-метки используются отдельно,
после миссии; последние доступны только диагностике симулятора.

## Внешние условия из конфигурации

Существующие `layer1.regime_metrics_for_config` сохраняются совместимыми.
В новой таблице они имеют префикс `regime_config_`.

| Поле после префикса | Формула | Единицы и смысл |
|---|---|---|
| `path_budget_m`, `safety_tmax_s`, `world_area_m2` | B, Tmax, Ax×Ay | м, с, м²; условия сравнения |
| `collection_coverage_ratio` | B W / A | 1; номинальная площадь полосы / акватория, без учета перекрытия |
| `drift_speed_mps` | v | м/с; фоновый дрейф, без отталкивания роботом |
| `drift_per_update_width`, `drift_per_60s_width` | vΔ/W; 60v/W | 1; снос относительно ширины |
| `camera_sigma_eff_m`, `radar_sigma_eff_m` | σ0 + k rdecay | м; ошибка на опорной дальности decay_range, не фактическая средняя ошибка |
| `camera_capture_uncertainty_ratio`, `radar_capture_uncertainty_ratio` | σeff/W | 1; ошибка относительно полной ширины, не вероятность захвата |
| `expected_camera_clutter_per_scan`, `expected_radar_clutter_per_scan` | λ θ R²/2 | отметок/обзор; θ в радианах, полный сектор, не обрезанный границей |
| `expected_clutter_per_s` | сумма ожидаемых ложных отметок / Δ | отметок/с; повторные отметки не равны уникальным ложным целям |
| `debris_density_per_m2` | n/A | объектов/м²; заданная синтетическая плотность |

## Снимки доступного роботу состояния

Все названия следующей таблицы имеют префикс `regime_` в событиях.
Версия схемы записывается как `regime_snapshot_version=1`.

| Поле | Формула | Единицы / оговорка |
|---|---|---|
| `response_time_nominal_s` | τ = Δ + d/u | с; номинальная задержка + прямой подход на скорости сбора; без разворотов и стоянки |
| `drift_response_width` | vτ/W | 1; снос за номинальное время реакции/подхода |
| `diffusion_response_width` | sqrt(4Dτ)/W | 1; двумерное RMS-смещение свободной диффузии; не учитывает границы/возмущение корпусом |
| `fresh_age_limit_s` | min(Tstale, W/v), при v=0 — Tstale | с; физическое рабочее определение свежести, не порог adaptive |
| `reachable_radius_m` | R = min(max дальностей сенсоров, max(0, B − пройденный путь)) | м; геометрический локальный радиус; не гарантия достижения с возвратом и маневрами |
| `reachable_area_m2` | число центров ячеек в круге R × dx×dy | м²; приближение пересечения круга с акваторией, зависит от сетки |
| `fresh_target_count` | число подтвержденных tracks с 0≤возраст≤fresh_age_limit и расстоянием≤R | tracks; оцененные цели могут быть ложными или объединенными |
| `fresh_target_density_per_m2` | fresh_target_count / reachable_area_m2 | tracks/м²; при нулевой площади неизвестно |
| `fresh_target_sigma_width_median` | median(σ свежих локальных tracks)/W | 1; без свежих tracks неизвестно |
| `map_concentration` | (N Σpi² − 1)/(N − 1), pi=mi/Σmi | 0…1; 0 — равномерная масса, 1 — одна ячейка; не доверие к карте и не ее точность |
| `queued_route_points` | число точек фактически оставшейся очереди | точек; 0 при отсутствии очереди |
| `queued_route_length_m` | сумма расстояний robot→p1→…→pk | м; текущая геометрия принятой очереди |
| `queued_route_time_nominal_s` | Tr = L/u + k Tdwell | с; номинальная экспозиция, без разворотов; не строгая верхняя/нижняя граница времени |
| `route_staleness_ratio` | Tr/Tstale | 1; время очереди / срок старения, **не вероятность** устаревания |
| `route_drift_width` | vTr/W | 1; снос за номинальное время очереди |

При нулевой массе карты или N≤1 концентрация неизвестна (`NaN`), не ноль.
У route-показателей нет привязки каждой точки к конкретному track, поэтому они
не включают исходный возраст цели в момент ее фактического достижения. Это явный
предел первого измерительного слоя, а не точная вероятность потери маршрута.
Влияние диффузии учитывается отдельно; правило свежести пока основано на фоне v.

## Итоги миссии и агрегирование

| Поле | Формула | Единицы / источник |
|---|---|---|
| `regime_outcome_empty_visit_fraction` | empty_goal_arrivals/evaluated_goal_count | 1; только оцениваемые завершенные заходы по действующей семантике simulation |
| `regime_outcome_wasted_path_fraction` | wasted_path_to_empty_goals/path_length_m | 1; незавершенный последний участок не объявляется пустым |
| `regime_outcome_false_marks_per_km` | 1000 false_detection_count/path_length_m | отметок/км; truth-labelled диагностика после миссии |
| `regime_outcome_false_to_true_marks` | false_detection_count/true_detection_count | 1; truth-labelled диагностика, при нуле true неизвестно |
| `regime_outcome_completed_leg_n` | число goal_completed с mode≠return и известной длительностью | участков; включает уточнения, не равно evaluated_goal_count |
| `regime_outcome_mean_completed_leg_time_s` | среднее goal_time_s выбранных завершений | с; включает реальное время разворотов/стояния; последний незавершенный участок цензурирован |
| `regime_outcome_mean_completed_leg_drift_width` | v × среднее goal_time_s / W | 1; фоновый снос за фактическую длительность завершенного участка |
| `regime_oracle_gap_auc`, `regime_oracle_gap_collected_ratio` | oracle_current_physics − режим | 1; парная разность, может быть отрицательной: oracle эвристический |

Для каждой динамической величины сохраняются `regime_goal_start_mean_<поле>` и
`regime_goal_start_valid_n_<поле>` — среднее конечных значений по назначениям
участков и его знаменатель. Это невзвешенные по времени средние; частота решений
и длительность участков зависят от политики. Сохраняются также число назначений,
число снимков и доля назначений с известной схемой (`regime_goal_snapshot_coverage`).
Нет снимков в старом журнале — нет динамической оценки; `NaN` не заменяется нулем.

Oracle соединяется только при полном совпадении не относящейся к planner части
config (включая seed, платформу, сенсоры, дрейф, сетку и поле), полного commit,
хеша исходников и среды, при clean provenance. Несколько совместимых повторов
одного режима отклоняются: входной набор должен содержать один повтор на ключ.
Если совместимого oracle нет, gap неизвестен и `regime_oracle_available=false`.
Старые/грязные запуски не получают oracle-pair автоматически по одному имени
сценария и seed. AUC разных версий также не смешивается таким соединением.

## Как использовать

```powershell
python -m cleanup_sim_v2.analyze_regimes --run-dirs out/audit/NEW_SERIES --out-dir out/audit/NEW_ANALYSIS
```

На вход подаются каталоги непосредственно с `*_manifest.json` отдельных запусков.
Проверяются хеши config/summary/events и совпадение config/summary с манифестом.
Читается сохраненная конфигурация целиком, а не текущие scenario defaults.
Выходной каталог должен быть новым. Создаются `regime_summary.csv` и
`analysis_manifest.json` с происхождением анализатора, входными и выходными хешами.
Исходные CSV не перезаписываются. Legacy summary без полного config и хешей
артефактов не выдается за проверенный вход; современные старые журналы без
снимков допустимы с явно неизвестными динамическими величинами.

Исходные параметры, онлайн-состояние и итоговые показатели используются по-разному.
Итоговые потери, false/true и oracle-gap нельзя подавать как заранее доступные
роботу признаки. Средние состояния зависят от выбранной политики; их связь с
качеством не доказывает причинности. Границы полезных режимов и интерпретируемое
правило еще требуют второго слоя чувствительности и отдельного протокола.

## Ограниченная проверка реализации

До проверки фиксируется smoke: `strong_drift`, seed 300, nominal, 60 м, 120 с;
adaptive, belief_horizon и oracle_current_physics. Три запуска проверяют только
наличие полей, сохранение/чтение и совместимость oracle. Это заведомо короткая
техническая миссия, не сравнение качества стратегий и не калибровка бюджета.
Тест инструмента отдельно сравнивает один seed с включенным снимком и с пустым
снимком: summary, series, старые события, карта и позиции должны совпасть точно.
