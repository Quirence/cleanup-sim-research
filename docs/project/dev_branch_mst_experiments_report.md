### Два новых режима планировщика

Оба переиспользуют существующую инфраструктуру (сенсорную модель, `TargetQueue`, вероятностную карту) без изменений — добавлена только логика выбора порядка объезда целей.

**`mst_route(start, targets, limit)`** ([cleanup_sim/planners.py](../../cleanup_sim/planners.py)) — новый алгоритм маршрутизации: строит полный граф из текущей позиции робота и всех подтверждённых целей, находит минимальное остовное дерево (алгоритм Прима), обходит его preorder-DFS (ближайший потомок первым). Используется как замена жадному nearest-neighbor (`nearest_neighbor_route`) в двух новых режимах:

- **`graph_mst`** — аналог существующего `detected_tsp`, но обход подтверждённых целей идёт через MST вместо nearest-neighbor. Без фазы исследования: если подтверждённых целей нет, использует стандартное `lawnmower`-покрытие.
- **`hybrid_mst`** — аналог существующего `hybrid` (переключатель explore/route по числу подтверждённых целей и энтропии карты), с той же exploration-логикой (`active`-скоринг), но ROUTE-фаза едет через MST, а не nearest-neighbor.

Оба режима **пересчитывают граф немедленно**, как только подтверждается новая цель во время объезда (не ждут завершения текущей пачки, в отличие от `detected_tsp`/`hybrid`) — реализовано через `should_invalidate_graph_route()`, единый хук в основном цикле симуляции.

Режимы доступны через CLI (`--mode graph_mst` / `hybrid_mst`), но **не входят** в `DEFAULT_MODES` — не участвуют в дефолтных сериях экспериментов.

## Эксперимент

Два прогона (одинаковые seed/сценарии/бюджеты — результаты по общим режимам воспроизводятся побитово):

```powershell
python -m cleanup_sim.run_experiments `
  --seeds 5 --scenarios clustered_base clustered_noisy uniform_base `
  --modes greedy lawnmower_dense detected_tsp hybrid graph_mst hybrid_mst `
  --out-dir out/cleanup_sim/hybrid_mst_probe --plot-examples
```

5 seed на сценарий/режим — быстрая прикидка, не публикационная статистика.

## Выводы

1. **MST vs nearest-neighbor (`graph_mst` vs `detected_tsp`)**: MST-обход стабильно немного лучше жадного ближайшего соседа — выше AUC и точность визитов во всех 3 сценариях, немного выше итоговый сбор в кластерных сценариях. Эффект реальный, но небольшой — ожидаемо для типичных (не патологических) раскладок точек.

2. **MST vs nearest-neighbor внутри hybrid (`hybrid_mst` vs `hybrid`)**: итоговая доля сбора почти не меняется (разница в пределах шума), но `hybrid_mst` стабильно тратит **на 6–11% меньше пути** на тот же результат и быстрее доходит до 80% сбора. MST здесь не увеличивает *количество* собранного, а делает объезд уже найденного эффективнее.

3. **Гипотеза "MST-гибрид приблизится к `greedy`" не подтвердилась.** Ни один из route-based режимов (`detected_tsp`, `hybrid`, `graph_mst`, `hybrid_mst`) не подбирается к `greedy` (100% сбор) или `lawnmower_dense` (91–96%). Во всех прогонах `hybrid`/`hybrid_mst` останавливаются по `stop_reason=time_budget`, не по `done`. Причина — структурная, а не алгоритмическая: маршрутизация по целям работает только с уже *подтверждённым* подмножеством мусора (сенсор должен увидеть объект дважды двумя разными сенсорами с достаточной уверенностью), и как только появляется хотя бы одна подтверждённая цель, `graph_mst`/`detected_tsp` больше никогда не возвращаются к систематическому покрытию карты. MST оптимизирует *порядок объезда того, что уже нашли*, а не *что вообще будет найдено* — поэтому не может закрыть этот разрыв.

4. **Практический итог**: если критична итоговая доля сбора — `greedy`/`lawnmower_dense` в этом наборе сценариев вне конкуренции. Если важна эффективность пути при сравнимом качестве целевой маршрутизации — `graph_mst`/`hybrid_mst` последовательно чуть лучше своих nearest-neighbor аналогов.
