# Первичная реализация `belief_cluster_route`

Дата: 2026-08-02.

## Зачем добавлен режим

После абляции `belief_horizon` стало ясно, что одношаговый выбор следующей точки уже близок к `greedy`, но остается далеко от `oracle_current_physics`. Основной разрыв возникает не из-за отсутствия еще одного веса в функции оценки, а из-за отсутствия маршрутного мышления: робот выбирает следующую цель, но не оценивает короткую последовательность близких полезных целей.

Поэтому добавлен экспериментальный режим `belief_cluster_route`. Он проверяет гипотезу: если карта и очередь подтвержденных целей содержат локальную группу вероятных объектов, робот может повысить эффективность, планируя короткий маршрут через эту группу, а не повторяя одношаговый выбор.

## Опора на литературу

Идея связана с несколькими направлениями:

- informative path planning: планирование пути под ограничением ресурса для максимизации полезности измерений;
- orienteering / TSP with profits: выбор маршрута по точкам с наградой при ограниченном бюджете;
- active mapping: учет неопределенности карты, но без прямого физического сбора;
- floating-waste USV path planning: прикладные маршруты для уборочных надводных аппаратов;
- camera/mmWave floating waste detection: вероятностная природа обнаружений и ложных целей.

Ближайшие источники для дальнейшего чтения:

- A. Singh et al., `Efficient Planning of Informative Paths for Multiple Robots`, IJCAI 2007.
- J. Binney, G. S. Sukhatme, `Branch and Bound for Informative Path Planning`, ICRA 2012.
- P. Vansteenwegen et al., `The Orienteering Problem: A Survey`, EJOR 2011.
- Y. Cheng et al., `FloW: A Dataset and Benchmark for Floating Waste Detection in Inland Waters`, ICCV 2021.
- `An Unmanned Vessel Path Planning Method for Floating-Waste-Cleaning USV`, Journal of Marine Science and Engineering, 2025.

## Что реализовано

Добавлен новый CLI-режим:

```powershell
python -m cleanup_sim_v2.run_experiments --modes belief_cluster_route
```

Измененные файлы:

- `cleanup_sim_v2/config.py`;
- `cleanup_sim_v2/planners.py`;
- `cleanup_sim_v2/simulation.py`;
- `cleanup_sim_v2/run_experiments.py`;
- `tests/test_cleanup_sim_v2.py`.

Режим использует только доступные планировщику данные:

- `DensityMap.expected_count`;
- подтвержденные `TargetQueue`-треки;
- параметры платформы и сенсоров;
- прогноз дрейфа треков, если он включен в конфиге.

Истинные координаты мусора не используются.

## Текущая логика алгоритма

1. Сначала вычисляется обычное одношаговое решение `belief_horizon`.
2. Если оно является уточнением цели, fallback, coverage-точкой или другим слабым действием, маршрут не строится.
3. Формируется набор кандидатов из подтвержденных целей и плотностных пиков карты.
4. По умолчанию продолжения маршрута разрешены только по подтвержденным целям:

```python
belief_cluster_route_confirmed_followups_only = True
```

5. Если рядом с основной целью есть подтвержденные цели, строится короткий маршрут до `belief_cluster_route_max_points`.
6. Если первая точка маршрута оказывается пустой, маршрут сбрасывается и область подавляется.
7. Если первая точка успешна, робот может продолжить движение по короткому маршруту.

Плотностные follow-up точки не удалены из кода, но отключены в дефолте, потому что первый smoke показал риск закрепления за ложными пятнами карты.

## Интерпретация

Режим пока нельзя считать основным алгоритмом статьи.

Положительное:

- режим запускается и проходит тесты;
- не использует oracle-доступ;
- действительно уменьшает число пустых целевых визитов;
- добавляет в проект маршрутную гипотезу, а не очередную настройку веса;
- дает основу для абляций: confirmed-only против density-followups.

Проблемное:

- доля сбора не улучшилась относительно `belief_horizon`;
- снижение пустых визитов не гарантирует рост полезного сбора;
- маршрутное закрепление может уводить робота от новых лучших наблюдений;
- текущая оценка маршрута недостаточно учитывает opportunity cost: что робот теряет, пока доезжает до хвоста маршрута;
- плотностные follow-up точки слишком чувствительны к ложным и размытым пятнам карты.

## Научный вывод на текущий момент

`belief_cluster_route` пока является не готовым вкладом, а диагностическим прототипом. Его ценность сейчас в том, что он показывает: простое добавление короткого маршрута поверх вероятностной карты недостаточно. Для публикационно сильного результата нужен настоящий receding-horizon/orienteering-подход с пересчетом маршрута после каждого наблюдения и явной моделью риска ложной цели.

## Следующие доработки

1. Перейти от “закрепленного маршрута” к receding-horizon исполнению:
   - строить маршрут для оценки;
   - исполнять только первый сегмент;
   - после каждого нового наблюдения пересчитывать горизонт.

2. Добавить вероятность истинности target-track:
   - хранить не только `confidence`, но и оценку `P(true target | detections, empty visits)`;
   - снижать вероятность после пустого визита;
   - учитывать возраст и сенсорный источник.

3. Ввести opportunity-cost в score:
   - сравнивать маршрут не только с текущей целью, но и с альтернативным лучшим одношаговым действием;
   - штрафовать продолжения, которые мешают добрать более надежные цели.

4. Сделать отдельную абляцию density-followups:
   - `confirmed-only`;
   - `confirmed + density`;
   - `confirmed + density + entropy`;
   - оценить, где именно появляются ложные пятна.

5. Сравнивать не только `collected_ratio`, но и `oracle_gap_collected_ratio`, `collected_mass_per_meter`, `wasted_path_ratio`, `goal_success_rate`.
