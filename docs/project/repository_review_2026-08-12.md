## 🔴 Critical

**Тесты абляций `belief_*` проверяют конфиг, а не поведение** — [tests/test_cleanup_sim_v2.py:320-382](../../tests/test_cleanup_sim_v2.py)

Все тесты на 6 научно значимых абляций (`belief_horizon_no_efficiency`, `_no_track_prediction`, `_no_refinement`, `belief_orienteering_depth1`, `_no_opportunity_cost`, `_density_disabled`) утверждают только `no_efficiency.planner.belief_efficiency_score is False` — то есть "поле датакласса выставлено правильно" — и ни разу не вызывают `choose_goal`/`run_simulation`, чтобы проверить, что абляция реально меняет решение планировщика.

Это ровно тот же класс бага, что был найден и исправлен на `dev` для `graph_mst`/`hybrid_mst`: мутационным тестом там было доказано, что три разных способа сломать алгоритм (свести к nearest-neighbor, отключить инвалидацию маршрута) не ловились ни одним тестом. Здесь — то же самое: если флаг `belief_track_prediction_enabled` ([cleanup_sim_v2/simulation.py:188](../../cleanup_sim_v2/simulation.py)) случайно перестанет что-либо отключать, ни один тест не упадёт. Для абляционного исследования (а весь научный вклад v2 сейчас строится на абляциях `belief_horizon`/`belief_orienteering`) это системный риск: можно опубликовать таблицу "ablation X убирает Y%", где на самом деле ablation X ничего не отключает.

**Что делать**: по образцу уже существующего в этом же репозитории правильного паттерна — [tests/test_hybrid.py:40-65](../../tests/test_hybrid.py) (`test_active_no_distance_removes_travel_penalty`, сравнивает скор до/после абляции) и [tests/test_graph_mst.py:220-259](../../tests/test_graph_mst.py) (сравнивает реальные маршруты) — для каждой абляции построить фиксированный сценарий и сравнить `decision.point`/`score_total` базовой и абляционной конфигурации.

## 🟡 Minor

- `PlannerConfig` — 71 поле, 55 с префиксом `belief_*`, плоский датакласс без группировки; работает, но масштабируется плохо (запуск с `mode="greedy"` таскает все 55 неиспользуемых belief-полей).
- `GoalDecision.expected_value` — для oracle-режимов это хардкод `1.0`, для belief-режимов — реальный многосоставной скор в произвольных единицах; название вводит в заблуждение.
- В тестах v2 — рыхлые assert-ы там, где сценарий уже точно сконструирован: `in {"density_peak", "density_transect", "entropy_peak"}` вместо точного значения; `"provisional_target" in kinds or "provisional_target_transect" in kinds` — тест не отличает, что из двух реально произошло.
- ~100-150 строк дублированного boilerplate в тестах v2 (9-аргументный вызов `choose_goal(...)` повторён 9 раз почти без изменений) — просится в фикстуру.
- `docs/project/` — 20 файлов, 8 из них датированные "дневниковые" отчёты за 1-2 августа без явной пометки "устарело/актуально", кроме `current_state.md` (который сам по себе хороший, актуальный якорь).
- `out/` локально уже 258 МБ (в git не попадает, но стоит иметь политику ротации/архивации, если счётчик экспериментов будет расти).
