## Что показывают пересчитанные числа

Средние по seed 330-339. Разность считается попарно: adaptive минус belief_horizon. AUC нормирован на бюджет пути и характеризует ранний/средний сбор в миссии; доля в последнем столбце относится только к ее концу.

| Сценарий | AUC belief | AUC adaptive | Разность AUC | Победы adaptive | Итоговый сбор belief / adaptive |
|---|---:|---:|---:|---:|---:|
| `static_calm` | 0.3006 | 0.2475 | -0.0532 | 1/10 | 51.07% / 43.67% |
| `weak_drift` | 0.3406 | 0.2689 | -0.0717 | 2/10 | 69.93% / 68.13% |
| `strong_drift` | 0.5446 | 0.5323 | -0.0123 | 5/10 | 83.27% / 90.67% |
| `robot_disturbed` | 0.3719 | 0.2992 | -0.0727 | 2/10 | 72.13% / 76.07% |

Средняя по четырем сценариям разность AUC равна -0.0525. Это описательное усреднение с равными весами сценариев. В `strong_drift` лучшая средняя AUC среди семи режимов без oracle у `belief_orienteering`: 0.5806; сравнение только с belief_horizon не заменяет сравнения со всеми baseline-ами.

В [таблице парных разностей](evidence/adaptive_review_2026-09-05/paired_adaptive_vs_horizon.csv) сохранены описательные percentile bootstrap интервалы: 20000 ресэмплов seed-пар, bootstrap seed 20260905, 95%, без поправки на множественные сравнения. Для `strong_drift` интервал разности AUC составляет примерно [-0.0571; 0.0316]. Он не доказывает не меньшую эффективность с допуском -0.02: нижняя граница выходит за допуск. Отсутствие убедительного превосходства и доказанная эквивалентность являются разными выводами.

Абляция включения route на двух seed в `strong_drift` дает среднее +0.0963 AUC, но отдельные эффекты равны -0.0099 и +0.2025. Это перспективный вопрос для проверки, а не устойчивое подтверждение полезности маршрутизации при дрейфе. Отражающие границы среды и накопление объектов у края дополнительно смешивают дрейф с изменением геометрии скоплений.

Равенство AUC полной версии и `no_hysteresis` наблюдается во всех восьми парах smoke. Оно не доказывает, что механизм удержания политики не работает вообще или что причина именно в масштабе 0.12. Для причинного объяснения нужны оценки конкурентов, моменты вызова selector-а, факты удержания и последующего override.

## Исправления интерпретации и диагностики

1. `choose_goal()` сначала продолжает `state.current_route`; до adaptive selector управление в этот момент не доходит. Поэтому утверждение о пересчете route/local маршрута после каждой точки неверно. Комментарии исправлены. Исполнение очереди сохранено, чтобы не смешивать проверку данных с новой алгоритмической версией.
2. В новые события добавлены `adaptive_selector_invoked`, `adaptive_route_continuation`, `adaptive_route_remaining_points`. Новая цель маршрута и новое решение о стратегии различаются.
3. `adaptive_policy_shares()` считает частоты selector-а только при полной разметке событий. Для старых/неполных журналов `count/share` и разделенные счетчики неизвестны (`NaN`, `share_basis=unavailable`); доступна лишь статистика всех участков. Восстанавливать неизвестные вызовы из названия политики нельзя.
4. Для всех четырех политик создаются нулевые строки при отсутствии выбора в конкретном запуске. При обработке старой агрегированной таблицы сначала выполняется pivot по scenario/seed с заполнением отсутствующих политик нулем и только затем среднее. Иначе редкая политика усредняется лишь по seed, где она появилась.

Пересчитанные старые доли **всех участков**, не новых решений:

| `weak_drift` | 56.259% | 40.212% | 0.850% | 2.680% |
| `strong_drift` | 58.761% | 41.239% | 0.000% | 0.000% |

Округление может менять сумму последнего знака. Исходные CSV сохранены; исправленные производные данные: [legacy_policy_execution_shares.csv](evidence/adaptive_review_2026-09-05/legacy_policy_execution_shares.csv).

## Ошибка статуса финальных seed

В тяжелой серии `layer1_postfix_heavy_2026-08-22` уже присутствуют 3840 строк для seed 100-129: 4 бюджета x 4 сценария x 8 режимов x 30 seed. Данные были просмотрены и использованы для выбора бюджета. Поэтому утверждение, что эти seed еще не использовались и остаются независимой финальной выборкой, неверно для проекта в целом. Сам коллега в этой ревизии их не запускал.

100-129 остаются допустимыми development/calibration данными, но будущая независимая проверка должна получить новый, заранее зарегистрированный диапазон после фиксации правил. Новый диапазон сейчас не запускается и не объявляется проверенным на отсутствие в чужих локальных экспериментах.

## Следующие действия

| Приоритет | Работа | Критерий завершения |
|---|---|---|
| 1 | Восстановить оригинальное окружение/исходный diff коллеги, получить один эталонный trace или воспроизвести серию на зафиксированной версии | Объяснено расхождение 143/128; есть точные версии, чистый commit и проверяемая траектория. Старые CSV сохраняются. |
| 2 | Согласовать горизонт оценки и горизонт исполнения | Явно выбрать: переоценка после участка или полная стоимость принятой очереди. Малое парное сравнение этих вариантов с новым журналом, без изменения физики. |
| 3 | Объяснить эффект route и hysteresis | Измерены длина принятой очереди, возраст целей при подходе, пустые участки, затраты до повторного выбора, моменты удержания/override; показана связь с AUC. |
| 4 | Завершить выбор базового бюджета | 3000 м остается кандидатом. После определения сравниваемых версий выполнить ограниченную проверку 2400/3000/3600 на общих seed; не повторять 3840 запусков для одного решения. |
| 5 | Второй слой чувствительности | Раздельно варьировать дрейф/возраст наблюдений, ошибку координат относительно ширины захвата, clutter, геометрию поля. Проверить влияние граничного накопления. Профили low/high меняют сразу несколько факторов и не дают причинного разделения. |
| 6 | Независимое подтверждение методики | Заранее зафиксированы вопросы, критерии рекомендации режима, параметры, бюджет, статистика и новая выборка. Затем финальная серия. |

Научная цель остается прежней: получить проверяемую методику выбора режима миссии по измеримым условиям. Наличие переключений само по себе не является вкладом; практическое правило должно объяснять и предсказывать пользу решения в пределах исследованных условий.
