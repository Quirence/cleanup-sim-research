# Восстановленная рабочая версия и дальнейшие направления

Дата: 2026-08-03.

## Что восстановлено

Код симулятора возвращен к лучшей зафиксированной рабочей версии:

```text
03c97df Improve belief planner scout behavior
```

Это версия с текущим базовым `belief_horizon` после улучшения начальной scout-логики. Временные экспериментальные режимы, не давшие устойчивого прироста, убраны из рабочего кода:

- patch-pass как основной режим;
- обязательная survey-фаза перед сбором;
- post-success mini-sweep;
- forced-transect вместо точечных целей;
- lifecycle-clear после успешного захвата;
- полный запрет density-кандидатов.

Архивные отчеты по этим проверкам оставлены в `docs/project`, чтобы не повторять неудачные направления.

## Главное понимание после повторного аудита

Разрыв с oracle нельзя закрыть простой полной разведкой. При бюджете `1000 м` обязательное покрытие акватории слишком дорого: робот видит больше объектов, но теряет путь, который мог быть потрачен на сбор.

Также не сработали простые усиления:

- один прямой проход через вероятностное пятно;
- жесткое удаление цели после захвата;
- локальный mini-lawnmower после каждого успеха;
- полное отключение неподтвержденной density-карты.

Значит перспективное направление должно быть не "больше покрытия" и не "длиннее проход", а более аккуратное управление риском.

## Наиболее правдоподобное направление

Рабочая идея:

> Риск-ограниченное вероятностное планирование, где неподтвержденные области карты используются только при достаточном отношении ожидаемой пользы к цене пути, а после подтверждения мусора робот выполняет одно короткое локальное действие и заново пересчитывает карту.

Что это должно исправить:

- базовый `belief_horizon` иногда едет к слабым вероятностным максимумам;
- полный запрет density-кандидатов помогает в статике, но вредит при дрейфе;
- локальная эксплуатация кластера полезна, но фиксированный mini-lawnmower слишком грубый;
- oracle выигрывает не TSP-магией, а серией коротких решений рядом с реальным кластером.

## Следующая реализация-кандидат

Название для отдельного режима:

```text
risk_gated_belief
```

Минимальная логика:

1. Сформировать обычные кандидаты `belief_horizon`.
2. Для неподтвержденных density/entropy-кандидатов считать risk-gate:
   - расстояние до цели;
   - ожидаемый сбор в физической swept-полосе;
   - локальная энтропия;
   - возраст/дрейф карты;
   - риск пустого визита.
3. Если gate не пройден, кандидат не запрещается навсегда, а временно проигрывает coverage/scout-кандидату.
4. После успешного сбора не запускать весь локальный маршрут, а выбрать одно короткое локальное действие из 3-5 вариантов.
5. После этого действия сразу вернуться к обычному пересчету.

## Как проверять

Сначала smoke:

```text
3 seeds x static_calm, weak_drift
```

Режимы:

```text
greedy
belief_horizon
risk_gated_belief
oracle_current_physics
```

Критерий продолжения:

- не хуже `belief_horizon` в обоих сценариях;
- прирост хотя бы `+0.02` в одном сценарии без провала в другом;
- `wasted_path_ratio` не выше базы более чем на `0.05`;
- победы над `greedy` сохраняются.

Если smoke пройдет, расширять до `10 seeds`.
