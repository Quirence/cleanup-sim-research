# Протокол разработочного эксперимента: горизонт adaptive

Дата фиксации: 2026-09-09. Статус: зафиксирован до запуска; эксперимент
завершён, результат приведён в
[отчёте](adaptive_horizon_experiment_report_2026-09-09.md).

## Решение пользователя и вопрос

Основной критерий эффективности — доля мусора, собранная к завершению миссии при
общем бюджете. Практическая цель — полная очистка, поэтому вместе с долей нужно
показывать число оставшихся объектов и частоту запусков с полной очисткой. AUC по
пути остается вторичной характеристикой темпа сбора.

Вопрос эксперимента: должен ли `adaptive_mission` продолжать всю принятую очередь
или после каждого завершенного участка снова выбирать режим по обновленному
состоянию? Сейчас utility нормируется по первому участку, а очередь
`confirmed_route` или `local_exploit` может исполняться без нового selector-вызова.

## Сравниваемые варианты

| Вариант | После завершения участка | Функция оценки |
|---|---|---|
| `queue_commit` | Продолжает оставшуюся очередь до исчерпания или инвалидирования | Текущая, с оценкой первого участка и rollout |
| `replan_each_leg` | Отбрасывает остаток adaptive-очереди и снова вызывает selector | Та же самая |

Меняется только `planner.adaptive_replan_after_each_leg`. Физика, сенсоры, карта,
candidate generation, веса utility и обработка цели остаются одинаковыми. Это
изолирует горизонт исполнения. Эксперимент не проверяет отдельную альтернативу с
полной стоимостью и полной пользой очереди: для нее нужна новая согласованная
функция оценки, которую нельзя смешивать с данным сравнением.

## Матрица

- сценарии: `static_calm`, `weak_drift`, `strong_drift`, `robot_disturbed`;
- профиль: `nominal`;
- бюджет пути: 3000 м; предел времени: 16500 с;
- новые разработочные seed: 400–409;
- два варианта горизонта, одинаковый seed внутри пары;
- всего 4 × 10 × 2 = 80 запусков;
- каждый запуск сохраняет config, summary, events, series, карту, позиции,
  полный provenance и хеши артефактов.

Seed 400–409 после запуска считаются просмотренными разработочными и не могут
использоваться как независимая финальная выборка. Бюджет 3000 м используется как
общая диагностическая точка и этим экспериментом не замораживается.

## Показатели

Основной:

- `collected_ratio` при общем лимите пути.

Показатели полноты очистки:

- `remaining_count = n_debris - collected`;
- `complete_cleanup = 1`, если не осталось ни одного объекта.

Вторичные диагностические:

- `auc_collected_by_path`, `sim_time_s`, `wasted_path_ratio`;
- `empty_goal_arrivals_per_km`, `goal_success_rate`;
- число selector-вызовов, продолжений очереди и отброшенных точек.

Единица сравнения — парная разность `replan_each_leg - queue_commit` для одного
scenario/seed. По каждому сценарию показываются средняя разность и 95% percentile
bootstrap interval. Общий результат сначала усредняет четыре сценария внутри
каждого seed, затем строит интервал по десяти seed-блокам; сценарные строки не
считаются независимыми повторами.

## Правило решения

Один объект соответствует `1 / 150 = 0.00667` доли при текущей конфигурации.
`replan_each_leg` выбирается без дополнительного согласования, если одновременно:

1. общая средняя прибавка не меньше одного объекта;
2. нижняя граница общего 95% интервала выше нуля;
3. ни в одном сценарии средняя потеря не достигает одного объекта.

Для `queue_commit` применяется симметричное правило. Во всех остальных случаях
результат признается неоднозначным: default не меняется, пользователю передаются
парные эффекты по сценариям, интервалы, остаток мусора и диагностические издержки.
AUC не отменяет однозначный вывод по итоговому сбору, но объясняет его цену.

## Валидность

- Запуск выполняется только на чистом commit и в новом output-каталоге.
- Матрица и config hashes проверяются при resume.
- Все остановки, пропуски и неполные пары показываются; строки не удаляются после
  просмотра результата.
- При изменении кода после начала серии эксперимент перезапускается в новом
  каталоге. Финальные seed, настройка весов и изменение физики не допускаются.

Команда после коммита реализации:

```powershell
python -m cleanup_sim_v2.run_adaptive_horizon `
  --seed-start 400 --seeds 10 `
  --scenarios static_calm weak_drift strong_drift robot_disturbed `
  --max-path-m 3000 --tmax-s 16500 `
  --out-dir out/adaptive_horizon_2026-09-09
```
