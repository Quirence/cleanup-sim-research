# Диагностика разрыва с oracle и быстрые гипотезы улучшения

Дата: 2026-08-03.

Статус после восстановления рабочей версии: архивный отчет по временным экспериментальным режимам. Режимы `survey_*`, `belief_horizon_post_sweep`, `belief_horizon_density_disabled`, `belief_horizon_no_patch_pass` и связанные ручки не входят в текущий рабочий код. Они были проверены как быстрые гипотезы и затем исключены из основной системы, поскольку не дали устойчивого улучшения.

## Цель

Понять, почему `oracle_current_physics` собирает существенно больше мусора, чем `belief_horizon`, и проверить наиболее правдоподобные направления улучшения без долгого перебора параметров.

Главная метрика: `collected_ratio` при бюджете пути `1000 м`.

## Что показала диагностика движения

`oracle_current_physics` не является оптимальным TSP-решателем. Он каждый раз выбирает ближайший живой объект из истинного состояния мира и подчиняется той же физике сбора, емкости, промахам и дрейфу.

Следовательно, разрыв с oracle в первую очередь отражает не качество TSP, а качество информации и локального выбора целей.

Пример: `static_calm`, seed `3`, `1000 м`.

| mode | collected_ratio | empty goals | wasted_path_ratio | unique true detections |
|---|---:|---:|---:|---:|
| `belief_horizon_no_patch_pass` | 0.240 | 39 | 0.396 | 107 |
| `greedy` | 0.280 | 56 | 0.600 | 135 |
| `oracle_current_physics` | 0.720 | 2 | 0.005 | 146 |
| `lawnmower_survey` | 0.000 | 9 | 0.899 | 117 |

Важный вывод: `lawnmower_survey` за 1000 м может увидеть много настоящего мусора, но почти не собирает его, потому что вся длина пути уходит на сенсорное покрытие, а физический сбор узкий.

## Проверенные гипотезы

### H1. Сначала выполнить полную или частичную разведку

Проверены режимы:

- `survey_belief_short`;
- `survey_belief_medium`;
- `survey_belief_long`;
- `survey_route_medium`;
- `survey_greedy_medium`.

Smoke:

```powershell
python -m cleanup_sim_v2.run_experiments --seeds 3 --scenarios static_calm weak_drift --modes belief_horizon_no_patch_pass survey_belief_short survey_belief_medium survey_belief_long survey_route_medium survey_greedy_medium oracle_current_physics --max-path-m 1000 --tmax-s 10000 --out-dir out\cleanup_sim_v2\survey_stage_hypotheses_1000m_3seed_2026-08-03 --checkpoint
```

Результат: обязательная разведочная фаза проиграла базовому `belief_horizon_no_patch_pass`.

Интерпретация: при метрике `collected_ratio@1000m` полная/длинная разведка слишком дорогая. Идея может быть полезна для больших бюджетов пути, но не как основной кандидат для текущей статьи.

### H2. Увеличить число рассматриваемых кандидатов

Проверено `belief_candidate_count = 60` и `100`.

Результат: изменений не дало на первых smoke-seed-ах.

Интерпретация: проблема не в том, что хороший кандидат просто отрезается лимитом `30`.

### H3. Отключить или ослабить refinement

Проверены:

- `belief_horizon_no_refinement`;
- увеличенные пороги `belief_collect_sigma_threshold_m`;
- измененный `belief_refine_standoff_m`.

Результат: полное отключение refinement ухудшает результат. Ослабление refinement дает только небольшой локальный эффект, не похожий на главный рычаг.

Интерпретация: уточнение цели нужно, потому что иначе растет число пустых визитов.

### H4. Чаще использовать проход через оцененную цель вместо точечного визита

Добавлена экспериментальная ручка:

- `belief_direct_target_candidates_enabled`.

Проверены варианты `transect_only`.

Результат: forced-transect уменьшает число пустых целей, но снижает общий сбор. Длинный проход часто вытесняет более полезные короткие доборы.

Интерпретация: физически осмысленный проход полезен не всегда; его нельзя включать вместо всех точечных визитов.

### H5. Удалять цель из очереди после успешного захвата

Добавлены параметры:

- `target_clear_after_direct_capture_enabled`;
- `target_capture_clear_radius_m`.

Результат: очистка после захвата улучшала некоторые static seed-ы, но ухудшала weak-drift поведение.

Интерпретация: в кластере повторные заходы рядом с уже собранной целью иногда полезны. Простое удаление цели не заменяет локальную эксплуатацию кластера.

По умолчанию очистка отключена, чтобы не портить базовый режим.

### H6. После успешного сбора выполнить короткий локальный прочес

Добавлен режим:

- `belief_horizon_post_sweep`.

Результат: текущая версия локального прочеса не дала прироста. В weak seed0 прочес собрал `3` объекта за `~63 м`, но вытеснил более полезные действия.

Интерпретация: идея локальной эксплуатации кластера правдоподобна, но простой мини-lawnmower после каждого успеха слишком грубый.

### H7. Запретить неподтвержденные density-цели

Добавлен режим:

- `belief_horizon_density_disabled`.

Smoke:

```powershell
python -m cleanup_sim_v2.run_experiments --seeds 5 --scenarios static_calm weak_drift --modes greedy belief_horizon_no_patch_pass belief_horizon_density_disabled oracle_current_physics --max-path-m 1000 --tmax-s 10000 --out-dir out\cleanup_sim_v2\density_disabled_gate_1000m_5seed_2026-08-03 --checkpoint
```

Результат:

| scenario | base `belief_horizon_no_patch_pass` | `belief_horizon_density_disabled` |
|---|---:|---:|
| `static_calm` | 0.184 | 0.204 |
| `weak_drift` | 0.251 | 0.214 |

Интерпретация: полный запрет density-целей полезен в статике, но вреден при слабом дрейфе, где неподтвержденная density-карта иногда первой выводит робота к кластеру.

## Текущий вывод

Гипотеза “полная разведка всей акватории” для главной метрики `1000 м` не подтверждается. Более правдоподобна не полная разведка, а риск-ограниченное использование неподтвержденной карты:

> Разрешать движение к неподтвержденным вероятностным областям только если ожидаемая польза достаточно велика относительно расстояния, неопределенности и риска пустого визита; после первого подтверждения переходить к локальной эксплуатации, но не фиксированным мини-lawnmower, а короткими действиями, пересчитываемыми после каждого шага.

## Наиболее правдоподобный следующий алгоритм

Рабочее название: `risk_gated_belief`.

Идея:

1. Пока нет подтвержденных целей, не выполнять обязательную полную разведку.
2. Разрешать неподтвержденные density/entropy цели только при прохождении risk-gate:
   - ограничение по расстоянию;
   - минимальная ожидаемая плотность вдоль физической swept-полосы;
   - штраф за пустой визит;
   - штраф за дрейф/старение карты.
3. После успешного сбора не запускать фиксированный локальный прочес, а пересчитать 3-5 коротких локальных действий и выбрать только одно лучшее.
4. После каждого локального действия заново обновлять карту и решать, продолжать кластер или вернуться к глобальному поиску.

Почему это сильнее, чем проверенные варианты:

- не тратит 250-750 м на обязательную разведку;
- не запрещает density-карту полностью;
- не делает длинный patch-pass через размытую вероятность;
- не стирает весь кластер после первого захвата;
- ближе к поведению oracle: короткие последовательные решения рядом с найденной областью.

## Что не стоит развивать дальше прямо сейчас

- Полная разведка всей акватории как основной режим для `1000 м`.
- Forced-transect вместо всех точечных целей.
- Post-success mini-lawnmower после каждого успешного сбора.
- Простое удаление всех целей рядом с захваченным объектом.
